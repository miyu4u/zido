# K-ECO 전기자동차 충전소 OpenAPI 연동 가이드

## 요약

한국환경공단(K-ECO)의 공식 서비스명은 **`한국환경공단_전기자동차 충전소 정보`**이며 공공데이터포털에서 신청한다. 서비스 식별자는 `B552584/EvCharger`, 오퍼레이션은 충전기 기본 정보용 `getChargerInfo`와 최근 상태 변경용 `getChargerStatus` 두 개다. 공식 상세 페이지는 2026-07-21 수정되었고, 첨부된 최신 활용가이드는 v1.25(2026-07-01)다. [C-001]

신규 연동은 공식 상세 페이지에 표시된 **HTTPS** 주소를 사용하고, 포털에서 발급한 서비스 키를 query parameter로 전달한다. 개발계정은 자동승인·1,000회이며 운영계정은 활용사례 등록 후 트래픽 증량을 신청할 수 있다. [C-002]

주의할 점은 공식 상세 페이지와 v1.25 가이드가 완전히 일치하지 않는다는 것이다. 상세 페이지는 기본 포맷을 XML로 표시하지만 가이드는 `dataType=JSON|XML`을 명시한다. 가이드의 요청표는 `statId`, `chgerId`, `dataType`을 필수로 표시하면서도 바로 뒤 목록 조회 예제에서는 `statId`와 `chgerId`를 생략한다. 상태 코드 `2`도 응답 필드 설명에는 `사용가능`, 공통 코드표에는 `충전대기`로 적혀 있다. 구현 전 승인 키로 최소 요청을 호출하여 실제 계약을 고정해야 한다. [C-003][C-004]

## 조사 범위와 방법

- 공식 공공데이터포털 상세 페이지, 해당 페이지의 v1.25 활용가이드, 공식 API 변경 공지를 직접 확인했다.
- 검색 결과와 블로그는 원문 발견에만 사용하고 기술 명세의 근거로 사용하지 않았다.
- 실제 인증키가 필요한 호출은 수행하지 않았다. 응답 예시는 공식 가이드의 필드 구조를 축약한 것이다.
- 기존의 자동변환 API, KSGA API, OCPI/OCPP는 이 문서의 범위 밖이다. 후보 비교는 `c20260814-234846_u20260814-235023__research-v1.md`를 참고한다.

## 핵심 발견

### C-001 — 공식 서비스는 두 조회 오퍼레이션을 제공한다

- **Claim type:** `direct_fact`
- **신뢰도:** high — 공공데이터포털 공식 상세 페이지와 한국환경공단 공식 활용가이드를 확인했다.
- **근거:** 서비스 ID는 `B552584/EvCharger`이며 `getChargerInfo`는 위치·타입·운영정보·이용조건·상태를, `getChargerStatus`는 최근 상태 변경과 상태 시각을 제공한다. [S-001][S-002]
- **제한:** 공개 문서는 평균 응답시간, TPS, 갱신 SLA를 숫자로 보장하지 않는다.

### C-002 — 신청·인증·쿼터는 공공데이터포털이 관리한다

- **Claim type:** `direct_fact`
- **신뢰도:** high — 공식 상세 페이지의 이용 조건과 오류표를 확인했다.
- **근거:** 무료, 공공저작물 출처표시 제1유형, 개발·운영 자동승인이다. 개발계정 신청 가능 트래픽은 1,000회이며 운영계정은 활용사례 등록 후 증량 신청이 가능하다. 서비스 키를 query parameter로 전달한다. [S-001]
- **제한:** 호출 한도와 승인 정책은 변경될 수 있으므로 배포 직전에 마이페이지의 승인 상세를 재확인한다.

### C-003 — 공식 자료 사이에 전송·파라미터 불일치가 있다

- **Claim type:** `direct_fact`
- **신뢰도:** high — 동일 서비스의 공식 페이지와 공식 v1.25 가이드를 대조했다.
- **근거:** 상세 페이지는 REST/XML과 `ServiceKey`를 표시한다. v1.25 가이드는 XML·JSON, `dataType`, 소문자 `serviceKey`를 표시한다. 가이드 요청표는 `statId`와 `chgerId`를 필수로 표시하지만 공식 예제는 두 값을 넣지 않은 목록 요청이다. [S-001][S-002]
- **제한:** 어느 표기가 게이트웨이에서 실제로 허용되는지는 인증키 없는 조사로 확정할 수 없다. 구현에서 자동 추정하거나 조용히 fallback하지 말고 계약 테스트로 고정한다.

### C-004 — 상태 코드는 원문값과 갱신 시각을 함께 보존해야 한다

- **Claim type:** `direct_fact`
- **신뢰도:** high — v1.25 가이드의 응답 명세와 공통 코드표를 확인했다.
- **근거:** 상태값은 `0`, `1`, `2`, `3`, `4`, `5`, `6`, `9`가 정의되어 있다. `statUpdDt` 등 시각은 14자리 문자열 예시로 제공된다. 같은 가이드 안에서 코드 `2`가 `사용가능`과 `충전대기`로 다르게 표기된다. [S-002]
- **제한:** 상태명 하나만 저장하면 명세 변경이나 소스 충돌을 복구하기 어렵다. `rawStatus`, 정규화 상태, 원천 갱신 시각을 분리한다.

### C-005 — 구형 자동변환 URL은 신규 구현에 사용하지 않는다

- **Claim type:** `direct_fact`
- **신뢰도:** high — 공공데이터포털의 공식 폐기·변경 공지를 확인했다.
- **근거:** 구형 `tn_pubr_public_elcty_car_chrstn_api`는 제공방식 변경으로 폐기 안내되었고 `EvCharger/getChargerInfo`, `EvCharger/getChargerStatus`로 전환되었다. 현재 상세 페이지는 HTTPS endpoint를 제시한다. [S-001][S-003]
- **제한:** 변경 공지 본문에는 HTTP가 남아 있으나 현재 상세 페이지의 HTTPS 주소를 우선한다.

## 이용 신청과 인증

1. [공공데이터포털 API 상세 페이지](https://www.data.go.kr/data/15076352/openapi.do)에서 로그인한다.
2. `활용신청`을 선택하고 개발계정 또는 운영계정을 신청한다.
3. 승인 후 마이페이지에서 서비스 키를 확인한다.
4. 키를 source code, fixture, URL 로그, 오류 메시지, telemetry에 기록하지 않는다.
5. URL을 조립할 때 키를 한 번만 URL encoding한다. 포털이 제공하는 일반 인증키와 인코딩 인증키를 혼용해 이중 encoding하지 않는다.
6. 운영 트래픽이 기본 한도를 넘으면 활용사례를 등록하고 증량을 신청한다.

공식 문서의 parameter 대소문자가 일치하지 않으므로 첫 smoke test에서 `ServiceKey`와 `serviceKey` 중 실제 승인 상세가 안내하는 표기를 사용하고 이를 fixture 기반 계약으로 고정한다.

## Endpoint

| 용도 | 현재 권장 URL | 설명 |
|---|---|---|
| 충전기 정보 | `https://apis.data.go.kr/B552584/EvCharger/getChargerInfo` | 위치, 운영기관, 충전기 타입, 이용조건, 상태 등 전체 snapshot |
| 충전기 상태 | `https://apis.data.go.kr/B552584/EvCharger/getChargerStatus` | 최근 상태 변경과 충전 관련 시각 조회 |

v1.25 가이드 본문·예제에는 HTTP URL과 전송 레벨 암호화 없음이 남아 있으나, 현재 공공데이터포털 상세 페이지는 HTTPS를 게시한다. 신규 구현은 HTTPS만 사용한다.

## 요청 명세

### 공통 parameter

| parameter | 가이드상 구분 | 설명 | 구현 주의사항 |
|---|---:|---|---|
| `serviceKey` / `ServiceKey` | 필수 | 공공데이터포털 인증키 | 공식 자료의 대소문자가 상충한다. 로그에서 반드시 마스킹한다. |
| `pageNo` | 필수 | 페이지 번호 | 1부터 순회하고 응답 `totalCount`를 기준으로 종료한다. |
| `numOfRows` | 필수 | 페이지 크기 | 최소 10, 최대 9,999. 큰 page는 timeout과 메모리를 고려한다. |
| `zcode` | 선택 | 시·도 코드 | 행정구역코드 앞 2자리. v1.25 코드표를 기준으로 관리한다. |
| `zscode` | 선택 | 상세 지역 코드 | 5자리 지역 상세 코드. |
| `kind` | 선택 | 충전소 구분 | 예: `A0` 공공시설, `B0` 주차시설. |
| `kindDetail` | 선택 | 충전소 상세 구분 | 예: `A001` 관공서, `B001` 공영주차장. |
| `statId` | 표에는 필수 | 충전소 ID | 목록 예제에서는 생략되어 있다. 실제 최소 요청으로 확인한다. |
| `chgerId` | 표에는 필수 | 충전기 ID | 목록 예제에서는 생략되어 있다. 실제 최소 요청으로 확인한다. |
| `dataType` | 표에는 필수 | `JSON` 또는 `XML` | 상세 페이지는 XML만 표시한다. 두 포맷을 각각 검증한다. |

### 상태 조회 전용 parameter

| parameter | 구분 | 설명 |
|---|---:|---|
| `period` | 선택 | 상태갱신 조회 범위(분). 기본 5, 최소 1, 최대 10. |

`period=5`는 5분 이내 갱신된 항목의 **조회 범위**이지 각 충전기의 상태가 5분 이내로 갱신된다는 SLA가 아니다.

### 계약 검증용 요청

아래는 문서화된 형태이며 실제 key를 저장소에 넣지 않는다.

```http
GET https://apis.data.go.kr/B552584/EvCharger/getChargerInfo
    ?serviceKey=<REDACTED>
    &pageNo=1
    &numOfRows=10
    &dataType=JSON
```

```http
GET https://apis.data.go.kr/B552584/EvCharger/getChargerStatus
    ?serviceKey=<REDACTED>
    &pageNo=1
    &numOfRows=10
    &period=5
    &dataType=JSON
```

승인 후 다음 조합을 소량 호출해 실제 계약을 확정한다.

1. `dataType=JSON`과 `dataType=XML`
2. `statId`·`chgerId` 생략 목록 요청
3. `zcode`·`zscode` 지역 필터
4. 단일 충전소·충전기 필터
5. 빈 결과와 마지막 페이지

### `getChargerStatus`

| 필드 | 의미 |
|---|---|
| `busiId` | 기관 ID |
| `statId`, `chgerId` | 충전소 ID, 충전기 ID |
| `stat` | 원문 상태 코드 |
| `statUpdDt` | 상태 변경·통신이상·통신복구 시각 |

공통 envelope에는 `resultCode`, `resultMsg`, `pageNo`, `numOfRows`, `totalCount`, `items`가 있다. 가이드 예시상 JSON은 `items.item` 배열이고 XML은 `items/item` 반복 구조다. 응답이 0건일 때 `items`가 누락되거나 다른 형태로 오는지는 실제 호출로 확인한다.

## 오류와 재시도

공식 상세 페이지가 안내하는 주요 gateway 오류는 다음과 같다.

| 코드 | 오류 | 처리 |
|---:|---|---|
| `01` | `APPLICATION_ERROR` | 제한된 backoff 재시도 후 장애로 기록 |
| `04` | `HTTP_ERROR` | method·URL 확인, 자동 재시도하지 않음 |
| `05` | `SERVICETIMEOUT_ERROR` | jitter를 둔 제한 재시도 |
| `10` | `INVALID_REQUEST_PARAMETER_ERROR` | 요청 계약 오류로 처리, 재시도하지 않음 |
| `12` | `NO_OPENAPI_SERVICE_ERROR` | endpoint·폐기 여부 확인 |
| `20` | 키 누락·권한 거부 | key와 활용승인 확인, 재시도하지 않음 |
| `22` | 일일 호출량 초과 | 수집 중단, 다음 초기화 또는 증량 신청 |
| `23` | 초당 호출량 초과 | backoff와 요청 속도 제한 |
| `29` | 차단 IP | 송신 IP와 포털 차단 여부 확인 |
| `30` | 미등록 인증키 | key·활용신청 확인 |
| `31` | 만료 인증키 | 이용기간 갱신 |

HTTP status만 보지 말고 응답 body의 `resultCode`와 `resultMsg`도 검사한다. 인증 오류 본문이나 요청 URL 전체를 로그에 남기지 않는다.

## 수집·저장 권고

- `getChargerInfo`를 전체/지역 snapshot 수집에, `getChargerStatus`를 짧은 주기의 변경 수집에 사용한다.
- `busiId + statId + chgerId`를 원천 복합 식별자로 보존하고 실제 중복 여부를 확인한다.
- `statUpdDt`(원천 갱신 시각)와 `observedAt`(우리 수집 시각)을 분리한다.
- `yyyyMMddHHmmss`는 timezone이 문서에 명시되지 않았으므로 임의로 UTC로 간주하지 않는다. 한국 현지 시각 가정은 제공기관 확인 전 별도 metadata로 표시한다.
- `delYn=Y`를 hard delete하지 말고 삭제 시각을 기록한 tombstone으로 처리한다.
- `parkingFree`가 비어 있으면 무료로 간주하지 않는다. 가이드는 현장 확인 대상으로 설명한다.
- `limitYn`, `limitDetail`, `useTime`, `note`, 상태 freshness를 사용자에게 숨기지 않는다.
- 전체 수집은 `totalCount`, `pageNo`, `numOfRows`로 마지막 페이지까지 순회하되 중복 제거와 page 간 변동을 허용한다.
- timeout, rate limit, schema validation 실패 시 마지막 성공 snapshot을 보존하고 stale로 표시한다.

- [ ] HTTPS endpoint만 허용
- [ ] 인증키 query·로그·trace 마스킹 확인
- [ ] key parameter 대소문자 계약 테스트
- [ ] JSON/XML 응답 각각 fixture 확보
- [ ] 목록 요청에서 `statId`·`chgerId` 생략 가능 여부 확인
- [ ] 빈 결과, 단일 item, 복수 item shape 검증
- [ ] `stat=2`, `6`, `9`의 제품 표시 정책 확정
- [ ] 시각 timezone을 한국환경공단에 확인
- [ ] `delYn`, stale, 이용제한 처리 검증
- [ ] gateway 오류별 재시도·중단 정책 검증
- [ ] 운영계정 트래픽 증량과 출처표시 반영

## 확인되지 않은 사항

공개 자료만으로 다음을 확정할 수 없다.

- 보장된 데이터 갱신 주기와 SLA
- 평균 응답시간과 초당 허용량의 구체적 숫자
- `statUpdDt` 등 14자리 시각의 공식 timezone
- 목록 조회에서 `statId`, `chgerId`, `dataType`의 실제 필수 여부
- JSON/XML 선택 시 실제 `Content-Type`과 빈 `items` shape
- 코드표 변경에 대한 별도 machine-readable version endpoint

이 항목은 추측으로 채우지 말고 승인 키 smoke test와 공공데이터포털 Q&A 또는 담당부서 문의로 확정한다.
