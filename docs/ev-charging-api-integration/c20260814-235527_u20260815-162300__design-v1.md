# 전기차 충전 상태 확인 — 아키텍처·User Facing Protocol·API Contracts

## 0. 문서 목적

이 문서는 `c20260814-234846_u20260814-235023__research-v1.md`의 조사 결과를 실제 구현에 넘길 수 있는 설계 계약으로 구체화한다. 대상은 다음 기능이다.

- 충전소를 위치와 반경으로 검색한다.
- 충전기별 현재 상태와 원천 갱신 시각을 보여준다.
- 데이터가 오래되었거나 원천 상태를 해석할 수 없을 때 이를 숨기지 않는다.
- 한국환경공단(KECO) 외부 API의 호출량·오류·인증키를 사용자 요청 경로와 분리한다.
- 동일 domain service를 HTTP API와 MCP tool에서 사용한다.

이 문서의 **사실**은 연구 보고서의 `C-001`~`C-010`과 `[S-*]` 출처를 따른다. 아래에서 “제안” 또는 “구현안”으로 표시한 내용은 저장소에 적용할 내부 계약이며 외부 기관의 공식 계약으로 해석하지 않는다.

## 1. 결정 요약

| 항목 | 결정 | 근거/상태 |
|---|---|---|
| MVP 상태 원천 | KECO `EvCharger`를 1순위로 사용 | 공식 HTTPS REST/XML 및 `statUpdDt` 확인 — 확정 사실 [C-001][C-002] |
| 호출 방식 | 수집기 → 정규화 저장소 → 내부 조회 API | 외부 quota와 사용자 latency를 분리 — 구현 제안 |
| 외부 호출 경로 | 사용자 HTTP/MCP 요청에서 직접 호출하지 않음 | quota·timeout·키 오류 격리 — 구현 제안 |
| 기본 도메인 경계 | `charger-domain`과 `charger-providers`를 `map-providers`와 분리 | 지도 검색과 충전 상태의 pagination/freshness 계약이 다름 [C-010] |
| 사용자 상태 의미 | `AVAILABLE`은 신선하고 매핑이 확인된 상태에만 사용 | stale/unknown을 사용 가능으로 오인하지 않도록 함 |
| 상태 코드 숫자 매핑 | 소스 버전별 설정으로 관리하고 미확인 값은 `UNKNOWN` | KECO 공식 페이지에서 전체 의미표가 확인되지 않음 [C-001] |
| 보완 원천 | KSGA는 schema·coverage·갱신 SLA 확인 후 선택 도입 | 승인형 REST/JSON API라는 사실만 확정 [C-006] |
| 차량 인증 정보 | 별도 `VehicleCatalogProvider`로 분리 | 충전기 실시간 상태의 대체재가 아님 [C-005] |
| 로밍/관제 | 로밍은 OCPI, 장비 관제는 OCPP로 별도 프로젝트화 | 서로 다른 계층 [C-008][C-009] |

### 1.1 이번 범위

- 읽기 전용 충전소·충전기 상태 확인
- KECO XML adapter, 페이지네이션, 수집·저장·신선도 계약
- 내부 HTTP JSON API
- MCP tool의 입력·출력 계약
- 오류, 재시도, quota, 보안, 관찰 가능성

### 1.2 이번 범위가 아닌 것

- 충전기 원격 시작·중지, 예약, 결제
- 사용자 차량 식별·개인정보 처리
- 사업자 간 로밍 세션·CDR·요금 정산
- 충전기와 CSMS의 WebSocket 관제
- KECO `getChargerInfo`의 미확인 세부 파라미터를 추정해 고정하는 것

## 2. 용어와 계약 계층

| 용어 | 의미 |
|---|---|
| station | 하나의 충전소. 위치와 운영·접근 정보를 가진다. |
| charger | 충전소에 속한 개별 충전기. `chgerId`로 식별한다. |
| source | 데이터를 제공한 원천. MVP에서는 `keco`, 선택적으로 `ksga`를 사용한다. |
| observedAt | 우리 수집기가 응답을 성공적으로 관찰한 시각이다. |
| statusUpdatedAt | 원천이 상태를 갱신했다고 전달한 시각이다. KECO의 `statUpdDt`에서 파싱한다. |
| freshness | 현재 시각 기준으로 상태를 신뢰할 수 있는 정도다. `FRESH`, `STALE`, `UNKNOWN`을 사용한다. |
| mapped status | 원천의 `rawStatus`를 소스별 매핑으로 해석한 내부 상태다. |
| effective status | 사용자에게 노출하는 상태다. 신선도 안전 규칙을 적용한 결과다. |
| snapshot | 수집기가 저장한 위치·상태의 읽기 전용 관측 결과다. |
| source summary | 응답에 포함된 각 원천의 마지막 성공·신선도·오류 요약이다. |

원천 API, domain, 사용자 transport를 다음 세 계약으로 분리한다.

```text
외부 계약                 내부 domain 계약              User Facing 계약
KECO XML / KSGA JSON  ->  canonical station/status  ->  HTTP JSON / MCP tool
       adapter + 검증          snapshot + freshness       안정된 enum + 오류 envelope
```

외부 필드명을 HTTP 또는 MCP 응답에 그대로 노출하지 않는다. 다만 진단과 사용자 판단을 위해 `source`, `rawStatus`, `statusUpdatedAt`, `observedAt`, `freshness`는 응답에서 보존한다.

## 3. 권장 아키텍처

```text
                     ┌──────────────────────────┐
                     │ Scheduler / Collector    │
                     │ 지역 분할 · lock · quota │
                     └────────────┬─────────────┘
                                  │
          ┌───────────────────────┼───────────────────────┐
          │                       │                       │
  ┌───────▼────────┐    ┌─────────▼───────┐    ┌──────────▼─────────┐
  │ KecoStatus     │    │ KecoInfo        │    │ KsgaStatus         │
  │ Provider       │    │ Provider        │    │ Provider (P1)      │
  │ HTTPS/XML      │    │ HTTPS/XML       │    │ 승인 후 검증       │

                     │ normalize · freshness    │
                     │ source conflict · query  │
                     └────────────┬─────────────┘

                     ┌──────────────────────────┐
                     │ Durable snapshot + cache │
```

### 3.1 저장소 배치 제안

기존 `Provider`는 `resolve`, `searchNearby`, `geocode`를 중심으로 하는 지도 계약이다. 충전 상태의 외부 pagination·원천 시각·상태 freshness를 이 계약에 추가하지 않는다.

```text
libs/
  charger-domain/
    src/
      contracts.ts       # domain input/output interfaces
      freshness.ts       # freshness와 effective status 규칙
      source-policy.ts   # source 우선순위·충돌 정책
      charger-service.ts # snapshot 조회 유스케이스
  charger-providers/
    src/
      keco/
        keco-status-provider.ts
        keco-info-provider.ts
        keco-xml-parser.ts
        keco-contracts.ts
      ksga/               # 승인·schema 확인 후 추가
  charger-storage/       # durable snapshot과 상태 upsert
apps/
  collector/              # 또는 기존 http app과 분리된 worker
  http-server/            # HTTP controller는 domain service만 호출
libs/mcp-runtime/         # charger_* tool 등록 및 domain 호출
```

`collector`가 별도 application으로 추가될 경우 source/runtime ownership과 구조 문서를 함께 갱신한다. 수집기가 HTTP controller를 호출해 데이터를 갱신하는 방식은 사용하지 않는다.

### 3.2 책임 규칙

| 컴포넌트 | 책임 | 금지 |
|---|---|---|
| provider adapter | endpoint 호출, query 생성, XML/JSON 파싱, 외부 오류 분류 | 사용자 메시지 생성, DB upsert |
| normalizer | ID·시각·상태 매핑, source/version 기록 | 원천 값을 임의로 보정하거나 삭제 |
| collector | 스케줄, 페이지 순회, lock, retry, quota guard, 관찰성 | 사용자 요청에 동기 응답 |
| storage | info/status snapshot 저장, idempotent upsert, 조회 인덱스 | 외부 API 호출 |
| charger domain | 반경 검색, 상태 필터, freshness/effective status 계산 | transport-specific envelope |
| HTTP controller | query validation, HTTP status/header, JSON 변환 | KECO XML 파싱·재시도 |
| MCP tool | tool schema, domain 호출, MCP 오류 변환 | 별도 provider 호출·별도 상태 규칙 |

## 4. Canonical domain contract

아래 TypeScript는 구현을 시작하기 위한 제안 계약이다. 문자열 ID와 원천 필드는 추정값으로 치환하지 않는다.

```ts
type ChargerSource = 'keco' | 'ksga' | 'other'

type Freshness = 'FRESH' | 'STALE' | 'UNKNOWN'

type MappedChargerStatus =
  | 'AVAILABLE'
  | 'CHARGING'
  | 'UNAVAILABLE'
  | 'MAINTENANCE'
  | 'UNKNOWN'
  | null

type EffectiveChargerStatus = Exclude<MappedChargerStatus, null>

type ChargerStatusRecord = {
  source: ChargerSource
  operatorId: string | null
  stationId: string
  chargerId: string
  rawStatus: string | null
  normalizedStatus: MappedChargerStatus
  status: EffectiveChargerStatus
  statusUpdatedAt: string | null
  observedAt: string
  freshness: Freshness
  sourceVersion: string | null
}

type ChargerStationRecord = {
  source: ChargerSource
  operatorId: string | null
  stationId: string
  name: string | null
  address: string | null
  location: { lat: number; lng: number } | null
  access: 'PUBLIC' | 'RESTRICTED' | 'UNKNOWN'
  chargers: ChargerStatusRecord[]
  sourceObservedAt: string
  sourceVersion: string | null
}
```

### 4.1 ID 규칙

- KECO 원천 식별자는 `busiId`, `statId`, `chgerId`를 각각 보존한다.
- domain의 station key는 최소 `(source, operatorId, stationId)`를 포함한다.
- charger key는 `(source, operatorId, stationId, chargerId)`다.
- 사용자 응답의 `stationId`는 충돌을 피하기 위해 예시처럼 `keco:ME:28260005` 형태의 opaque string을 사용한다. 구현 시 path segment encoding을 적용한다.
- `statId + chgerId`가 상태와 정보의 안정적인 join key인지 KECO 최신 가이드와 fixture로 확인한 뒤 고정한다. 확인 전에는 서로 다른 레코드를 자동 병합하지 않는다.
- 주소·좌표가 같다는 이유만으로 서로 다른 source의 station을 하나로 합치지 않는다.

### 4.2 상태 규칙

`normalizedStatus`는 원천 상태 매핑의 결과이고, `status`는 사용자에게 안전하게 보여줄 최종 상태다.

다음 불변식을 지킨다.

1. `status = AVAILABLE`이면 반드시 `normalizedStatus = AVAILABLE`이고 `freshness = FRESH`여야 한다.
2. `freshness = STALE`이면 `normalizedStatus`가 `AVAILABLE`이어도 `status = UNKNOWN`으로 반환한다.
3. 원천 코드가 매핑되지 않거나 시각을 파싱할 수 없으면 `normalizedStatus = UNKNOWN`, `status = UNKNOWN`으로 보존한다.
4. `CHARGING`, `UNAVAILABLE`, `MAINTENANCE`는 매핑이 확인된 경우에만 사용한다. 매핑되지 않은 숫자를 추정하지 않는다.
5. stale/unknown 상태를 빈 결과로 삭제하지 않는다. 검색 결과에서 보여주되 신선도와 시각을 함께 제공한다.

### 4.3 Freshness 규칙

내부 TTL은 UX·quota·수집 주기에 맞춰 설정값으로 둔다. KECO 요청의 `period`는 원천 조회 조건이지 서비스 freshness 보장시간이 아니다.

| 조건 | freshness | 사용자 `status` 영향 |
|---|---|---|
| `statusUpdatedAt`가 유효하고 내부 TTL 이내이며 정상 수집됨 | `FRESH` | 매핑된 상태를 사용 |
| `statusUpdatedAt`는 있으나 TTL 초과 또는 마지막 snapshot fallback | `STALE` | `AVAILABLE`을 `UNKNOWN`으로 격하 |
| 원천 시각 없음·파싱 실패·clock skew 의심 | `UNKNOWN` | `UNKNOWN` |

`observedAt`를 새 수집 시각으로 덮어써서 오래된 원천 상태를 fresh로 연장하지 않는다. 이전 snapshot을 반환하더라도 원래의 `statusUpdatedAt`와 마지막 성공 `observedAt`를 유지한다.

`statUpdDt`의 원문은 보존한다. 날짜 형식과 timezone 해석이 최신 활용가이드에서 확정되기 전에는 파싱 실패를 성공으로 간주하지 않는다.

## 5. External provider contracts

### 5.1 KECO 상태 API

공식 상태 endpoint는 다음과 같다.

```http
GET https://apis.data.go.kr/B552584/EvCharger/getChargerStatus
  ?ServiceKey=<SERVICE_KEY>
  &pageNo=1
  &numOfRows=9999
  &period=5
  &zcode=11
Accept: application/xml
```

확인된 요청 계약은 다음과 같다.

| 파라미터 | 필수 | 규칙 |
|---|---:|---|
| `ServiceKey` | 예 | 공공데이터포털 발급 키. 로그·trace·오류에서 값과 query 전체를 마스킹한다. |
| `pageNo` | 예 | 1 이상의 페이지 번호 |
| `numOfRows` | 예 | 10 이상 9,999 이하. 전체 건수는 `totalCount`로 확인한다. |
| `period` | 아니오 | 상태갱신 조회 범위(분), 1~10, 기본 5 |
| `zcode` | 아니오 | 시·도 코드. 운영 설정으로 관리하고 코드 목록을 하드코딩하지 않는다. |

성공 여부는 HTTP status만으로 판단하지 않는다. XML의 `header.resultCode`가 성공값이 아니면 HTTP 200이어도 provider 오류로 분류한다.

최소 파싱 필드는 다음과 같다.

```ts
type KecoStatusItem = {
  busiId: string | null
  statId: string | null
  chgerId: string | null
  stat: string | null
  statUpdDt: string | null
}

type KecoStatusPage = {
  resultCode: string
  resultMsg: string
  pageNo: number
  numOfRows: number
  totalCount: number
  items: KecoStatusItem[]
}
```

공식 샘플의 XML 형태는 다음과 같다. 이 예시는 필드 모양을 설명하기 위한 fixture이며 `stat=2`의 제품 표시명을 단정하지 않는다.

```xml
<response>
  <header>
    <resultCode>00</resultCode>
    <resultMsg>OK</resultMsg>
  </header>
  <body>
    <items>
      <item>
        <busiId>ME</busiId>
        <statId>28260005</statId>
        <chgerId>02</chgerId>
        <stat>2</stat>
        <statUpdDt>20190829121020</statUpdDt>
      </item>
    </items>
  </body>
</response>
```

### 5.2 KECO 기본 정보 API

기본 정보 endpoint 자체는 다음으로 확인되었다.

```http
GET https://apis.data.go.kr/B552584/EvCharger/getChargerInfo
```

그러나 현재 조사에서 전체 요청·응답 표가 상태 API와 동일하게 노출되지는 않았다. 따라서 다음을 **구현 전 차단 조건**으로 둔다.

1. 최신 `v1.25` 활용가이드에서 필수 파라미터와 응답 필드를 확보한다.
2. 승인 키로 소량 호출해 key를 제거한 XML fixture를 만든다.
3. `statId + chgerId`와 주소·운영·충전기 타입의 join 규칙을 검증한다.
4. 정보 snapshot과 상태 snapshot을 별도 upsert 경로로 저장한다.

가이드와 fixture가 없을 때는 `getChargerInfo`의 미확인 필드를 코드에 추정해서 추가하지 않는다.

### 5.3 Provider interface 제안

```ts
type ProviderPage<T> = {
  pageNo: number
  pageSize: number
  totalCount: number
  items: T[]
  sourceObservedAt: string | null
}

type ChargerStatusQuery = {
  pageNo: number
  pageSize: number
  periodMinutes: number
  regionCode?: string
}

interface ChargerStatusProvider {
  readonly source: ChargerSource
  fetchStatusPage(
    query: ChargerStatusQuery,
  ): Promise<ProviderPage<ChargerStatusInput>>
}

interface ChargerInfoProvider {
  readonly source: ChargerSource
  fetchInfoPage(
    query: ChargerInfoQuery,
  ): Promise<ProviderPage<ChargerInfoInput>>
}
```

adapter는 성공 데이터만 domain에 넘긴다. 실패 시 다음과 같은 명시적 분류를 반환하거나 예외로 전달한다.

```ts
type ProviderFailureKind =
  | 'TIMEOUT'
  | 'RATE_LIMITED'
  | 'QUOTA_EXHAUSTED'
  | 'AUTHENTICATION'
  | 'INVALID_REQUEST'
  | 'CONTRACT_CHANGED'
  | 'BLOCKED_NETWORK'
  | 'UPSTREAM_UNAVAILABLE'
```

### 5.4 KSGA·차량 인증·표준 프로토콜 경계

- KSGA는 신청·승인·Service Key·접근 IP가 필요한 REST/JSON 보완 provider다. 실제 endpoint, schema, 사업자 범위, 갱신 SLA를 확인하기 전에는 `ksga` 결과를 KECO와 자동 병합하지 않는다.
- 환경부·국립환경과학원 차량 인증 API는 차량 모델·인증·1회충전주행거리 metadata 용도다. `VehicleCatalogProvider`로 분리하고 충전 상태 조회 계약과 공유하지 않는다. 실제 호출 URL은 승인 후 가이드/Swagger로 확정한다.
- OCPI는 CPO↔MSP 로밍 계약이다. 위치·가용성·요금·세션·CDR가 필요해질 때 별도 adapter와 partner contract를 둔다.
- OCPP는 충전기↔CSMS 운영 프로토콜이다. 직접 관제가 필요할 때만 WebSocket, 인증서, 연결 상태 머신, 적합성 시험을 별도 설계한다.

## 6. User Facing Protocol

### 6.1 공통 원칙

1. 사용자 요청은 저장된 snapshot을 조회한다. 요청마다 KECO/KSGA를 호출하지 않는다.
2. 모든 성공 응답은 `dataAsOf`, source, freshness를 포함한다.
3. `AVAILABLE`은 “현재 시각 기준으로 신선하고 매핑이 확인된 사용 가능 상태”라는 의미로 제한한다.
4. `UNKNOWN`은 데이터 없음·매핑 불명·오래된 상태를 구분하지 못한다는 뜻이 아니라, 응답의 `freshness`, `rawStatus`, 시각 필드와 함께 원인을 판단할 수 있게 한다.
5. stale/unknown을 빈 배열로 바꾸지 않는다.
6. 내부 provider 오류의 원문, Service Key, 외부 URL query는 사용자에게 반환하지 않는다.

### 6.2 HTTP API 공통 계약

Base path는 `/v1`이다. 응답 시간과 저장소 선택은 domain service가 결정하며 controller는 transport 변환만 담당한다.

#### 성공 응답 envelope

```ts
type ChargingApiMeta = {
  requestId: string
  generatedAt: string
  dataAsOf: string | null
}

type ChargingApiSourceSummary = {
  source: 'keco' | 'ksga' | 'other'
  lastSuccessfulObservedAt: string | null
  freshness: 'FRESH' | 'STALE' | 'UNKNOWN'
  itemCount: number
  errorCode?: string
}

type ChargingApiResponse<T> = {
  data: T
  meta: ChargingApiMeta
  sourceSummary: ChargingApiSourceSummary[]
}
```

`dataAsOf`는 응답에 포함된 상태 관측 중 대표 시각이다. 서로 다른 source 또는 charger의 시각이 다르면 가장 최신 시각 하나로 모든 항목이 같은 시각에 갱신된 것처럼 표현하지 않는다. 상세 항목의 `observedAt`와 `statusUpdatedAt`가 최종 기준이다.

#### 오류 응답 envelope

```ts
type ChargingApiError = {
  error: {
    code:
      | 'INVALID_ARGUMENT'
      | 'INVALID_CURSOR'
      | 'NOT_FOUND'
      | 'SNAPSHOT_UNAVAILABLE'
      | 'RATE_LIMITED'
      | 'INTERNAL_ERROR'
    message: string
    retryable: boolean
    details?: Record<string, string | number>
  }
  meta: { requestId: string }
}
```

`details`에는 필드명, 허용 범위, retry-after 같은 안전한 정보만 넣는다. `ServiceKey`, Authorization 값, 외부 raw response body는 넣지 않는다.

### 6.3 주변 충전소 검색

```http
GET /v1/charging-stations
  ?lat=37.5665
  &lng=126.9780
  &radiusM=3000
  &status=AVAILABLE
  &limit=20
  &cursor=<opaque-cursor>
  &source=keco
```

#### 요청 파라미터

| 파라미터 | 필수 | 제안 규칙 |
|---|---:|---|
| `lat` | 예 | -90 이상 90 이하의 decimal |
| `lng` | 예 | -180 이상 180 이하의 decimal |
| `radiusM` | 아니오 | 기본 3,000m. 양의 정수이며 서비스 최대 반경은 설정값으로 제한 |
| `status` | 아니오 | `AVAILABLE`, `CHARGING`, `UNAVAILABLE`, `MAINTENANCE`, `UNKNOWN` 중 하나. 미지정이면 전체 |
| `freshness` | 아니오 | `FRESH`, `STALE`, `UNKNOWN`, `ANY`. 미지정이면 전체를 반환하되 각 항목에 표시 |
| `source` | 아니오 | `keco`, `ksga`, `other`. 미지정이면 활성 source 정책 적용 |
| `limit` | 아니오 | 기본 20, 최대 100 |
| `cursor` | 아니오 | 서버가 발급한 opaque cursor만 허용 |

`status=AVAILABLE` 필터는 effective status에 적용한다. 따라서 stale snapshot의 내부 `normalizedStatus=AVAILABLE` 레코드는 이 필터에 포함하지 않는다.

#### 응답 예시

```json
{
  "data": {
    "items": [
      {
        "stationId": "keco:ME:28260005",
        "operatorId": "ME",
        "name": "예시 충전소",
        "address": "서울특별시 ...",
        "location": { "lat": 37.5665, "lng": 126.978 },
        "access": "PUBLIC",
        "distanceM": 84,
        "chargers": [
          {
            "chargerId": "02",
            "status": "UNKNOWN",
            "normalizedStatus": "AVAILABLE",
            "rawStatus": "2",
            "freshness": "STALE",
            "statusUpdatedAt": "2019-08-29T12:10:20+09:00",
            "observedAt": "2026-08-14T00:00:00Z",
            "source": "keco"
          }
        ]
      }
    ],
    "nextCursor": null,
    "matchedCount": 1
  },
  "meta": {
    "requestId": "req_01...",
    "generatedAt": "2026-08-14T00:00:02Z",
    "dataAsOf": "2026-08-14T00:00:00Z"
  },
  "sourceSummary": [
    {
      "source": "keco",
      "lastSuccessfulObservedAt": "2026-08-14T00:00:00Z",
      "freshness": "FRESH",
      "itemCount": 1
    }
  ]
}
```

`normalizedStatus`와 `status`를 함께 반환하는 이유는 “원천 상태는 사용 가능으로 매핑되지만 데이터가 stale하여 지금 사용 가능하다고 보장할 수 없음”을 표현하기 위해서다. UI의 기본 표시와 `status` 필터는 `status`를 사용해야 한다.

#### HTTP 결과

| 상황 | HTTP |
|---|---:|
| 정상 조회, item 0 포함 | 200 |
| query validation 실패 | 400 `INVALID_ARGUMENT` |
| cursor가 만료·변조됨 | 400 `INVALID_CURSOR` |
| 해당 영역 snapshot이 아직 한 번도 성공하지 않음 | 503 `SNAPSHOT_UNAVAILABLE` |
| client rate limit 초과 | 429 `RATE_LIMITED` |
| 저장소 또는 domain 오류 | 500 `INTERNAL_ERROR` |

유효한 snapshot이 있고 원천이 현재 장애라면 200으로 stale 결과를 반환한다. 마지막 snapshot조차 없을 때만 503으로 구분한다.

### 6.4 충전소 상세 조회

```http
GET /v1/charging-stations/{stationId}
```

- `stationId`는 list 응답에서 받은 opaque ID를 그대로 사용한다.
- path decoding 후 내부 source·operator·station 식별자를 검증한다.
- station metadata와 모든 charger의 상태를 함께 반환한다.
- station은 존재하지만 상태 snapshot이 없으면 station metadata를 반환하고 각 charger 상태를 `UNKNOWN`으로 표시한다.
- station이 snapshot에 없으면 404 `NOT_FOUND`다.

응답의 charger contract는 주변 검색과 동일하다. 두 endpoint가 서로 다른 상태 매핑이나 freshness 계산을 사용해서는 안 된다.

### 6.5 HTTP cache와 header

다음은 초기 운영 기본값에 대한 구현 제안이며 환경별 설정으로 둔다.

```http
Cache-Control: public, max-age=30, stale-while-revalidate=120
ETag: "snapshot-<version>"
Vary: Accept, Accept-Encoding
X-Request-Id: req_01...
```

- ETag는 snapshot 버전 또는 query 결과 버전으로 계산한다.
- 외부 `ServiceKey`를 cache key나 response header에 포함하지 않는다.
- HTTP cache가 오래된 응답을 허용하더라도 body의 `freshness` 규칙을 우회하지 않는다.

### 6.6 MCP User Facing protocol

저장소의 `mcp-runtime`은 HTTP/stdio transport와 분리된 동일 domain service를 등록한다. MCP tool은 외부 KECO API가 아니라 snapshot 조회만 호출한다.

#### `charger_search_nearby`

입력 schema 제안:

```ts
{
  lat: number
  lng: number
  radiusM?: number
  status?: 'AVAILABLE' | 'CHARGING' | 'UNAVAILABLE' | 'MAINTENANCE' | 'UNKNOWN'
  freshness?: 'FRESH' | 'STALE' | 'UNKNOWN' | 'ANY'
  source?: 'keco' | 'ksga' | 'other'
  limit?: number
  cursor?: string
}
```

출력은 HTTP API의 `data`와 동일한 domain shape을 사용한다.

```json
{
  "items": [],
  "nextCursor": null,
  "matchedCount": 0,
  "dataAsOf": "2026-08-14T00:00:00Z",
  "sourceSummary": []
}
```

- tool 설명에 “상태 시각과 freshness를 확인하라”는 사용자 안내를 포함한다.
- `status=AVAILABLE`은 HTTP와 동일하게 effective status에 적용한다.
- 유효한 snapshot이 없으면 MCP tool 결과를 `isError: true`로 반환하고 안정된 `SNAPSHOT_UNAVAILABLE` 코드를 제공한다.
- provider raw body나 키 관련 세부사항은 tool text에 포함하지 않는다.

#### `charger_status`

입력 schema 제안:

```ts
{
  stationId: string
  chargerId?: string
  source?: 'keco' | 'ksga' | 'other'
}
```

출력은 station metadata, 선택된 charger 또는 전체 chargers, `sourceSummary`, 각 상태의 `statusUpdatedAt`, `observedAt`, `freshness`를 포함한다.

- `chargerId`가 없으면 station의 모든 charger를 반환한다.
- station은 있으나 charger가 없으면 domain 결과를 빈 charger 배열로 반환한다.
- 식별자가 없으면 `NOT_FOUND`, snapshot 자체가 없으면 `SNAPSHOT_UNAVAILABLE`로 구분한다.
- MCP tool 등록은 HTTP controller가 아니라 `mcp-runtime`의 공통 registration에서 소유한다.

### 6.7 사용자 표시 문구 권고

상태 enum을 최종 UI 문구와 직접 결합하지 않는다. 기본 문구는 다음 의미를 따른다.

| effective status | 기본 표시 의미 |
|---|---|
| `AVAILABLE` | 사용 가능 — 단, 응답의 `freshness=FRESH`를 함께 표시 |
| `CHARGING` | 충전 중 |
| `UNAVAILABLE` | 사용 불가 |
| `MAINTENANCE` | 점검 중 |
| `UNKNOWN` | 상태 확인 불가 |

`UNKNOWN`을 “사용 불가”로 번역하지 않는다. `statusUpdatedAt`이 오래되었거나 원천 숫자를 해석하지 못한 것일 수 있으므로 `freshness`, 마지막 관측 시각, source를 함께 보여준다.

## 7. Collector protocol

### 7.1 수집 흐름

```text
1. 지역 작업 획득
2. provider별 quota/rate limiter 확인
3. getChargerStatus page 1 호출
4. XML HTTP + resultCode 검증
5. totalCount 기준 다음 페이지 생성
6. 각 item normalize
7. status snapshot upsert
8. 모든 페이지 성공 시 지역 수집 commit
9. source summary/metrics 기록
10. lock 해제
```

한 페이지가 실패하면 해당 지역의 수집 run을 부분 성공으로 가장하지 않는다. 이미 성공한 이전 snapshot은 유지하되 새 `observedAt`으로 연장하지 않는다. 페이지별 임시 결과는 run ID로 격리하고, 전체 성공 기준을 만족할 때만 최신 snapshot 포인터를 전환한다.

### 7.2 페이지네이션·중복

- `pageNo`, `numOfRows`, `totalCount`는 외부 계약대로 전달하고 내부 조회 API에는 외부 page 번호를 노출하지 않는다.
- 수집 run의 idempotency key는 `(source, regionCode, collectionWindow)`로 구성한다.
- 상태 upsert key는 `(source, operatorId, stationId, chargerId)`다.
- 동일 run을 재실행해도 레코드 수가 증가하지 않아야 한다.
- 상태와 정보 upsert를 한 transaction으로 묶지 않는다. 하나가 지연되어 다른 하나의 최신성을 덮지 않아야 한다.

### 7.3 동시성·quota

- 기본은 수요 기반 지역 수집과 짧은 cache다. 전국을 고정 1분 주기로 polling하지 않는다.
- 지역별 동시성을 제한하고, 일일 quota의 안전 여유분을 남긴다.
- 개발계정 1,000회, KSGA 500회/일 등의 조사 시점 값은 계정·정책에 따라 바뀔 수 있으므로 배포 전 재확인한다.
- 운영계정 증량이 승인되더라도 무제한 polling을 허용하지 않는다. 실제 item 수·응답 시간·상태 변경률을 측정한 뒤 주기를 결정한다.
- 여러 collector replica가 실행될 때 distributed lock 또는 단일 leader를 사용한다.

## 8. 오류와 재시도 계약

| 외부 오류/상황 | 분류 | collector 정책 | 사용자 영향 |
|---|---|---|---|
| timeout, `SERVICETIMEOUT_ERROR(05)` | 일시적 | 제한된 횟수의 exponential backoff + jitter | 이전 snapshot을 200 stale로 반환. 없으면 503 |
| `APPLICATION_ERROR(01)` | 원인 미상 | 짧은 1회 재시도 후 circuit 기록 | 이전 snapshot 우선 |
| `INVALID_REQUEST_PARAMETER_ERROR(10)` | 영구 요청 오류 | 재시도 금지, adapter 수정 알림 | 이전 snapshot 유지 |
| `NO_OPENAPI_SERVICE_ERROR(12)` | 계약·폐기 | 즉시 중단, endpoint/버전 확인 | source stale 또는 503 |
| 키 누락·권한 `20` | 설정 오류 | 재시도 금지, secret/config 알림 | source stale 또는 503 |
| 일일 한도 `22` | quota | 해당 provider 중지, reset 대기 | stale 결과와 source 상태 표시 |
| 초당 한도 `23` | rate limit | Retry-After 준수, 없으면 동시성 축소 | 정상 snapshot이 있으면 200 |
| 차단 IP `29` | 네트워크 정책 | 재시도 금지, egress IP 확인 | source stale 또는 503 |
| 미등록 키 `30`, 만료 키 `31` | 인증 설정 | 재시도 금지, 운영 알림 | source stale 또는 503 |
| HTTP 200 + 비성공 `resultCode` | application failure | body code 기준으로 위 정책 적용 | HTTP status를 성공 근거로 삼지 않음 |
| XML/JSON schema parse 실패 | 계약 변경 | raw 제한 격리, snapshot 갱신 중지 | `UNKNOWN`/`STALE`, 계약 변경 알림 |

재시도는 같은 잘못된 query 또는 인증 오류에 적용하지 않는다. 외부 response body 전체를 로그하지 않으며, 진단이 필요한 경우 key가 제거된 제한적 fixture만 별도 보관한다.

## 9. 보안·개인정보·운영 방침

### 9.1 인증키

- Service Key는 secret manager 또는 환경변수로 주입한다.
- 코드, 문서, test fixture, 로그, trace span, error message에 기록하지 않는다.
- URL logger는 query 전체를 redact하고, 일반 cache key에도 키를 넣지 않는다.
- KSGA는 신청 IP와 실제 egress IP가 일치하도록 배포 설정을 고정·감시한다.
- 외부 HTTPS 통신에서 TLS 검증을 끄지 않는다.

### 9.2 관찰 가능성

최소 metric/tag는 다음과 같다.

```text
provider, endpoint, region, resultCode, httpStatus,
latencyMs, itemCount, runId, observedAt, sourceUpdatedAt,
freshness, retryCount, quotaState
```

다음 조건은 알림 대상이다.

- 연속 timeout 또는 전체 지역 수집 누락
- XML/JSON schema parse failure
- key/permission 오류
- quota 22 또는 rate limit 23 반복
- stale 비율 상승
- `statUpdDt` 파싱 실패율 상승
- source 간 coverage 차이 또는 동일 ID 충돌 증가

### 9.3 데이터 보존

- raw source 값과 정규화 결과를 분리 보관한다.
- 원천 식별자와 시각을 삭제하지 않는다.
- raw XML은 운영 로그가 아니라 접근 제한된 contract fixture 또는 격리 저장소에만 보관한다.
- 차량 인증 API를 추가하더라도 차량 식별정보와 충전기 상태를 불필요하게 결합하지 않는다.

## 10. 데이터 품질·소스 충돌

### 10.1 source 우선순위

초기에는 KECO 단독으로 서비스하고, KSGA 도입 시에도 source별 관측 결과를 우선 보존한다. “KECO가 항상 진실” 또는 “가장 최신 시각이 항상 우선”이라는 전역 규칙을 만들지 않는다.

병합이 필요한 경우 최소 조건은 다음과 같다.

1. 동일 사업자·station·charger 식별자가 확인된다.
2. 두 source의 source version과 관측 시각이 기록되어 있다.
3. 매핑 충돌과 freshness가 source summary에 남는다.
4. 자동 병합이 불가능하면 두 결과를 별도 station으로 반환하거나 후보 관계로 남긴다.

### 10.2 보정 금지 규칙

- 좌표가 없다고 상태 이력을 삭제하지 않는다.
- `statusUpdatedAt`이 없다고 `observedAt`을 대신 넣어 fresh로 만들지 않는다.
- 미확인 status 숫자를 `AVAILABLE` 또는 `UNAVAILABLE`로 추정하지 않는다.
- 정보 snapshot이 늦다고 최신 상태가 오래된 위치를 덮도록 하지 않는다.
- 빈 결과를 provider 성공으로 기록하지 않는다. 실제 빈 결과와 수집 실패를 구분한다.

## 11. 구현 순서와 acceptance criteria

### Implementation status (2026-08-15)

P0 read-only MVP implementation is present in the workspace:

- `libs/charger-providers`: official KECO v1.25 sanitized status/info fixtures, bounded XML
  parser, ServiceKey redaction, resultCode failure classification.
- `libs/charger-storage`: local Node 22 SQLite snapshot store with transactional upsert,
  TTL metadata, and typed lock errors.
- `libs/charger-domain`: canonical freshness/effective status, cache-aside single-flight,
  bounded pagination, stale fallback, location filtering, and opaque station detail.
- `apps/http-server`: `/v1/charging-stations` list/detail controllers with stable envelopes,
  request IDs, ETag, and cache headers.
- `libs/mcp-runtime`: `charger_search_nearby` and `charger_status` registered beside the
  unchanged `place_*` tools.

The default test suite uses sanitized fixtures and injected fetch/store doubles. A live
KECO call remains opt-in and requires an approved `KECO_SERVICE_KEY`; it is not a CI gate.
SQLite remains single-node/local-file only, and source mapping is versioned as `keco-v1.25`.

### P0 — KECO 단독 read-only MVP

1. domain contract와 effective status/freshness 테스트를 먼저 고정한다.
2. Service Key 없이 동작하는 공식 성공·실패 XML fixture를 작성한다.
3. `getChargerStatus` adapter의 query validation과 페이지 순회를 구현한다.
4. 상태 snapshot storage와 idempotent upsert를 구현한다.
5. `/v1/charging-stations`와 station detail API를 snapshot-only로 연결한다.
6. `charger_search_nearby`, `charger_status` MCP tool을 같은 domain service에 등록한다.

### P1 — 계약 확인 및 보완

- 최신 KECO 가이드에서 `stat` 숫자별 의미를 확인하고 source-version mapping을 확정한다.
- `getChargerInfo`의 전체 필드·join key를 승인 키 fixture로 확정한다.
- KSGA 승인 후 endpoint·JSON schema·사업자 coverage·갱신 SLA를 확인한다.
- 차량 인증 API 승인 후 URL·파라미터·변경 이력을 별도 provider로 확정한다.

### 검증 기준

- `resultCode=00` 성공 XML을 전체 페이지로 파싱한다.
- `pageNo`, `numOfRows`, `period`, 잘못된 `zcode`의 경계를 검증한다.
- 오류 05/10/12/20/22/23/29/30/31의 재시도 여부가 표와 일치한다.
- `statUpdDt`가 TTL을 넘으면 `freshness=STALE`이고 public `status=UNKNOWN`이다.
- 원천 상태 매핑이 없으면 `normalizedStatus=UNKNOWN`이다.
- 중복 upsert가 `(source, operatorId, stationId, chargerId)` 레코드 수를 증가시키지 않는다.
- 외부 provider가 timeout이어도 기존 snapshot은 stale로 조회된다.
- snapshot이 전혀 없을 때만 `SNAPSHOT_UNAVAILABLE`이 반환된다.
- HTTP와 MCP가 동일한 station/status/freshness 결과를 제공한다.
- Service Key가 로그·오류·trace·fixture에 남지 않는다.
- 외부 키 없는 기본 CI는 parser/domain/API contract 테스트만 실행하고 live smoke test는 opt-in으로 둔다.

## 15. 최종 권고

첫 release는 **KECO 상태 수집기 + durable snapshot + freshness-aware domain + HTTP/MCP read-only protocol**로 제한한다. KSGA, 차량 인증, OCPI, OCPP를 같은 provider interface에 억지로 넣지 않는다.

특히 사용자에게 `AVAILABLE`을 반환하는 경로는 다음 세 조건을 모두 만족해야 한다.

```text
원천 상태 매핑 확인
        AND
statusUpdatedAt이 내부 TTL 이내
        AND
해당 snapshot 수집이 성공적으로 commit됨
```

그 외 결과는 원천값과 관측 시각을 보존한 `UNKNOWN` 또는 `STALE`로 표시한다. 이 계약을 먼저 고정하면 외부 API가 변경되거나 보완 source가 추가되어도 사용자-facing 의미가 흔들리지 않는다.
